# Running this project

Clone the repo with `git clone https://github.com/milhud/diffusion_downscaling_model` and set up a Python environment with PyTorch, xarray, xESMF, numpy, and matplotlib (on NCCS Discover this is `module load python/GEOSpyD/24.3.0-0/3.12`). The model's trained weights are not stored in git — they live on Hugging Face. The current, up-to-date checkpoint set (`drn_best.pt`, `vae_best.pt`, `diffusion_best.pt`, `diffusion_latest.pt`) is in the private repo `mudhil/era5-conus404-diffusion-downscaling`; pull it into a local `checkpoints/` directory with `hf download mudhil/era5-conus404-diffusion-downscaling --local-dir checkpoints/`. There is also a public archive, `mudhil/diffusion-downscaling-checkpoints`, which has current DRN/VAE weights but an older diffusion checkpoint, and `mudhil/diffusion-downscaling-model`, a much larger (2.6 TB) repo that bundles checkpoints together with the full 41-year raw CONUS404 training dataset (`conus404_yearly_1980.nc` … `conus404_yearly_2020.nc`) — only pull that one if you actually need the raw data, using `hf download mudhil/diffusion-downscaling-model --local-dir data/ --include "conus404_yearly_*.nc"`. Input ERA5 files are expected as `data/era5_{year}.nc` and CONUS404 target files as `data/conus404_yearly_{year}.nc`; if you're only running inference against already-trained weights you don't need the CONUS404 targets, just ERA5 input and, ideally, the preprocessed cache described below.

Most of the actual scripts assume you've built a preprocessing cache first, since re-regridding ERA5 to the CONUS404 grid on the fly is slow. Run `python -m src.preprocessing.cache_builder --all` (or the parallel SLURM version, `sbatch scripts/run_preprocess.sh`) to produce `cached_data/era5_{year}.npy`, `cached_data/conus_{year}.npy`, `cached_data/static_fields.npy`, and `cached_data/nan_days.json`. You can sanity-check the result with `python scripts/verify_preprocessing.py --plot` and `python -m src.preprocessing.verify_cache`. Normalization statistics are computed once from the training years and cached to `norm_stats.npz`; both training and inference load this file rather than recomputing it, so make sure it's present (it's a small file and is checked into the repo).

For a quick look at what the model is doing without running full diffusion sampling, `python -m src.inference.sample_nc --checkpoint_dir checkpoints --cache_dir cached_data --plot_dir sample_plots --device cuda` loads the DRN and VAE checkpoints, pulls a handful of samples from the cached validation set, and writes comparison plots (ERA5 input, CONUS404 target, DRN prediction, DRN+VAE reconstruction) — this doesn't touch the diffusion stage and only works against cached data, not an arbitrary input file. The actual full three-stage pipeline (DRN → VAE → diffusion ensemble) is exposed as a library function, `run_pipeline()` in `src/inference/pipeline.py`, which takes a normalized ERA5 tensor plus the three loaded models and returns both the DRN's deterministic prediction and an ensemble of diffusion samples; it isn't wired up as a standalone CLI for arbitrary new ERA5 files yet. The closest thing to a working example of driving it end-to-end is `src/evaluation/event_predict.py`, which tiles a 512×512 window, runs `run_pipeline()` per tile with configurable ensemble size and denoising steps, blends overlapping DRN tiles with a Hann-window taper, inverts the log1p transform and unit conversion on precipitation, and writes out physical-unit `.npz` arrays — run it with `python -m src.evaluation.event_predict --members 8 --steps 16 --events <event_name>` (omit `--events` to run all ten catalogued benchmark events) as a template for scoring your own inputs. Whatever you do, load checkpoints in the order DRN → VAE → diffusion, since the diffusion model's conditioning is built from the VAE-encoded DRN prediction — see `src/evaluation/_eval_setup.py:load_models` for the canonical loading code.

Training is a three-stage sequential process — DRN first, then the VAE (needs `checkpoints/drn_best.pt`), then the diffusion model (needs both DRN and VAE checkpoints) — driven by `train.py` and configured entirely through `config.py` (variable list, patch size, per-stage epochs/learning rates, EMA decay, loss weights, and the 1980–2014/2015–2017/2018–2020 train/val/test year split). The simplest way to run it is `sbatch run_training.sh`, which launches `torchrun --standalone --nproc_per_node=4 train.py --stage all --data_dir data --checkpoint_dir checkpoints --cache_dir cached_data --plot_dir train_plots` on 4 A100 GPUs via SLURM DDP; pass `--stage drn`, `--stage vae`, or `--stage diffusion` to `sbatch run_training.sh` to run just one stage. Full training is estimated at roughly 400k steps (~40 hours), which exceeds the `alla100` QOS's 12-hour wall-clock cap, so in practice you resume repeatedly with `python train.py --stage <stage> --resume`, which restores model weights, optimizer state, LR scheduler, and (for diffusion) EMA weights from the `*_latest.pt` checkpoint and continues from the next epoch. Rather than resubmitting manually, `./scripts/resume drn`, `./scripts/resume vae`, or `./scripts/resume diffusion` starts a daemon that polls the SLURM job every two minutes and automatically resubmits with `--resume` up to 20 times; watch it with `tail -f train_loop.log` and stop it with `kill $(cat .train_daemon.pid)`. Checkpoints are written at the end of every epoch, so at most one epoch of progress is lost if a job is killed by the walltime limit. After the diffusion stage finishes, `train.py` runs a small held-out evaluation comparing DRN-only RMSE against the full diffusion-ensemble RMSE and, on the main process, auto-commits and pushes `train_plots/` to git — worth knowing if you're running this unattended and don't want that push to happen.
